# Shared decisions

Decisions that affect more than one part. Project decisions live in each part: `nidana/docs/DECISIONS.md` (N-numbers) and `sambhasha/docs/DECISIONS.md` (D-numbers). The Case Library follows these shared decisions and its own SPEC.

Status as of 25 Sep 2026: every entry is **agreed**, decided by Dr Atul Tiwari. A new proposal is marked **Proposed** until he confirms it. Change an agreed decision only with his explicit approval, as a new entry that supersedes the old one.

| Id | Decision | Why | Status |
| --- | --- | --- | --- |
| S-001 | **Umbrella.** `Research_Projects/Clinical-Case-Sim` holds three parts: `case-library/`, `nidana/` and `sambhasha/`. | Keeps the projects together, so neither is misplaced or changed without the other knowing. | Agreed |
| S-002 | **One shared case library.** Claude curates each case once through the Supabase MCP; Atul reviews it; it is frozen and exported as a case bundle that both Nidana and Sambhasha import. | One curation and one review per case, and results from students and from AI that can be compared. Consolidates N-002, N-003 and Sambhasha D-021, which stay as the project-level records. | Agreed |
| S-003 | **Names.** Nidana is the game. Sambhasha is the research simulator (formerly the Virtual Diagnostic Team, VDT; code id `sambhasha`). The Case Library holds the Case Vault (Supabase project `case-vault`, schema `casevault`). The umbrella is Clinical-Case-Sim. | *Sambhāṣā* is the Charaka Saṃhitā's term for structured discussion among physicians: friendly consultation (*sandhāya*) and challenging debate (*vigṛhya*), which match Sambhasha's Consultants and its Challenger. | Agreed |
| S-004 | **Shared contract and change protocol.** The contract (bundle format, catalogue ids, origin labels, licence flags, price and turnaround tables, scoring structure) changes only through the Case Library, with Atul's approval, a versioned entry in `docs/CHANGELOG.md`, and an acknowledgement from each part. Each part pins the versions it supports. | Stops one project from silently breaking the other. | Agreed |
| S-005 | **Repository.** One private Git repository at the umbrella root (GitHub: `clinical-case-sim`). Sambhasha's research release is a separate public repository, generated from it by an allow-listed export at submission. A held-out set of cases stays private. Details in `docs/REPOSITORY.md`; day-to-day Git rules in `CLAUDE.md`. | Shared-contract changes land in one commit; answers stay private until publication; the benchmark is protected from contamination. | Agreed |
| S-006 | **Licences in development and in release.** Development and internal testing may use CC BY-NC and ND cases, and every figure as published, including figures with arrows or labels. ND cases stay in Atul's own testing: testers outside see only cases whose licence allows sharing adaptations. Every case, and every figure separately, carries licence flags, and the Case Studio marks NC and ND cases "Development only". The store release uses CC0 and CC BY cases (CC BY-SA only if Atul accepts sharing that case's adapted content under CC BY-SA), and only figures Atul has cleared. The public research release excludes ND cases. Articles without an open licence are not curated. Supersedes Sambhasha D-012. | Atul's instruction: more cases to test with now, a clean release later. | Agreed |
| S-007 | **One development database until the store release.** The Case Vault's Supabase project also holds the development game's play data, with one migration history kept in the Case Library. Testers use pseudonymous accounts. The production database (self-hosted Supabase on the VPS, no MCP) is created before the store release, and only production-eligible bundles are published into it. | Atul's instruction: everything before the store release is development. Pseudonymous testers keep personal data out of a project that Claude can query. | Agreed |
| S-008 | **Case Studio.** A basic, private CMS in the Case Library for viewing and accessing cases during development: read-only first, with review decisions added later if Atul prefers them to Excel. | Atul's request (N-013 feedback). Both projects use the same cases, so the Studio belongs to the library. | Agreed |
| S-009 | **Stack across the parts.** Case Library: Supabase (Postgres), Python scripts and a Next.js Case Studio. Nidana: an Expo player app, a Next.js game server and a TypeScript engine. Sambhasha: the Python engine as designed. | Each part keeps its language; the bundle JSON is the bridge. | Agreed |
